Trusted agent graphs

Visual agent canvases are everywhere, and long agent runs are everywhere. Separately they fail you: the canvas still needs a human builder, and the long run is a black box you can’t safely promote.

The bet

Lock the architecture first, let Claude build the graph, run it to the goal in a sandbox, then you only review and promote.

The loop

  1. Grill features · tools · perms · tests →
  2. Claude builds the graph →
  3. Sandbox iterate to the goal →
  4. You review →
  5. Promote to prod

What the graph is

  • Inspectable flow of CLI / script nodes
  • Permissions set per node by the user
  • Browser, cloud, and apps as nodes that run that CLI
  • Every change must pass tests before it’s trusted
  • A good graph becomes a reusable nested module

First proof

A ticket-to-PR harness, packaged as a Claude Code plugin. One ticket per chat. Claude plans it, builds it, tests it, and opens the PR. I step in three times: to approve the plan, to merge, and to close.

  1. You start a ticket →
  2. Plan steps · test gate · evidence →
  3. You approve the plan →
  4. Build in its own worktree →
  5. Checker runs the test gate, red loops back →
  6. Reviewer diff vs plan →
  7. You merge the PR
  • Only I can run the three commands: start, sync and end. Claude can’t trigger them itself
  • A guard hook checks every shell command and blocks merging, pushing to main, and force pushes
  • Two subagents start with a fresh context: a checker that only runs the test gate and reports proof, and a reviewer that reads the diff against the plan. Neither one edits files
  • Build and test loop until the gate is green, and the loop stops if the same failure comes up three times
  • Each ticket gets a canvas page rendered from one data file: plan, steps, evidence and PR state
  • A ticket can’t close until every evidence item is proven and the PR is merged
  • So far it has opened 4 ticket PRs, and I’ve merged 2 of them

Before this: a marketing-email drafting workflow built as a graph of 23 nodes and 28 edges. A content gate stops the run when there’s no real copy, and three pauses wait for a human. A 9-step live test passed, ending in an unpublished CMS draft.

What this proves: Claude can run the middle of the loop by itself, inside clear limits, with proof checked by an agent that didn’t write the code, and the whole thing installs as a plugin. What it doesn’t prove yet: the plan is a list of steps written for each ticket, not a graph of CLI nodes that Claude builds from a grilled spec. Permissions come from one guard on shell commands, not from settings on each node. The work runs in a git worktree, not an isolated sandbox. And running many tickets in parallel from one chat isn’t verified yet.

What it is not yet

A chat UI that drives this — later. Economics — when we have real numbers.

The edge

Not another drag-and-drop canvas. The edge is pre-decided architecture, an AI-authored graph, a sandbox until it’s done, and one human gate to prod.
